# dem2mesh Simplifier (Part A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `dem2mesh --tolerance T` writes a triangulated irregular network (TIN) whose vertical error at every grid sample is at most T model units, so flat ground costs almost nothing and full-resolution windows above today's 25,000,000-vertex cap become possible.

**Architecture:** Three new units in `demmesh`: exact integer predicates on grid coordinates, a one-dimensional profile simplifier (Douglas and Peucker, vertical distance), and the greedy-insertion TIN that simplifies a grid chunk by chunk with each chunk's sides simplified first, so chunks share boundary vertices exactly. `SolidMesh` is generalised to build walls and a base from any surface with an ordered boundary. `dem2mesh` gains the flag, a `simplify:` summary line, a `memory:` dry-run line, and caps that count the written mesh rather than the grid.

**Tech Stack:** C++20, Catch2 v3.16.0, CLI11 v2.7.2, CMake + Ninja; no new dependency.

**Spec:** `docs/superpowers/specs/2026-10-21-simplify-and-tiles-design.md`, sections 1 to 4, 6, 7 (Part A), 8 and 9. Part B (footprints and tiles) is a later plan.

## Global Constraints

- C++20, `-Wall -Wextra` clean, the conventions of `CLAUDE.md`; headers included as `"mesh/<Name>.h"`; namespace `demdl::mesh`.
- No new external dependency: the triangulation is written in-house with exact integer predicates (spec 3).
- Predicates are exact for chunk sides up to 16,384 cells; the chunk lattice is 2048 x 2048 cells without tiles (spec 4.5); a chunk side above 16,384 is refused.
- The simplifier's guarantees (spec 4.3): every vertex is a grid sample at its exact height; the four corners are vertices and the rectangle's sides hold only boundary vertices; the vertical error at every grid sample is at most the tolerance; one sheet, counter-clockwise seen from above, no overlaps, gaps or unused vertices; deterministic.
- `--tolerance` is in model units after `--z-scale` and `--scale`, above 0, with no default: absent means today's full grid, byte for byte (spec 4.1, 6).
- With `--tolerance` the 25,000,000 cap and the 4,000,000 warning count the written mesh, not the grid (spec 4.2); the grid may be as large as the window.
- The dry run simplifies too, so its counts and sizes are exact (spec 4.7).
- Memory: the window and the grid are each held once as float32; everything else is per chunk or proportional to the output (spec 3).
- Tests stay offline; Blender only in the background; test names must not begin with `-`; never `git add -A`; nothing is written into `~/Downloads`.
- Commit messages end with the attribution line of the model doing the work.

## Deviations from the spec (deliberate, small)

1. **The `simplify:` line has no thousands separators** (`1002001 grid vertices to 61230`), matching every other count the summary prints; the spec's example is illustrative. Task 8 updates the example.
2. **A sample on an edge shared by two triangles may be scanned by both** while the TIN is built: its error is the same against the shared edge in either, so the guarantee and the insertion order are unaffected. The spec's "exactly once" is kept for the final error check, which visits each sample once.
3. **A plane over several chunks gives two triangles per chunk**, not two in all: spec 4.5 accepts the chunk seams, and spec 4.3's two-triangle rule is pinned for a grid that fits one chunk.

## Review Focus

1. A tolerance far below the heights' own resolution, 1e-9, must end with every deviating sample a vertex, never loop: pinned in Task 4.
2. A grid of 2 rows or 2 columns must give the corners only and a valid box or ribbon: Task 4.
3. A spike or a step exactly on a chunk seam or corner must survive (the side profile keeps it) and the seam must stay closed: Task 5.
4. `--tolerance 0.1 --scale 0.02 --z-scale 2` means 2.5 m: the conversion divides by both and the summary prints it: Task 7.
5. A full-resolution window above 25,000,000 vertices is accepted with `--tolerance` and its memory stated, and still refused without: Task 7.

  ```cpp
  struct GridPoint { std::int32_t x, y; };
  inline constexpr std::int32_t kMostPredicateCoordinate = 16384;
  // (b - a) x (c - a): > 0 when a, b, c turn counter-clockwise in a frame with x to the right and y up, < 0 clockwise,
  // 0 when in line. Exact for |coordinates| <= kMostPredicateCoordinate (the products stay inside 64 bits).

  // For a, b, c counter-clockwise: > 0 when d lies inside their circumcircle, < 0 outside, 0 on it. Exact under the
  // same bound: the determinant is at most about 12 x 16384^4, under 2^63.
  [[nodiscard]] std::int64_t inCircle(GridPoint a, GridPoint b, GridPoint c, GridPoint d) noexcept;
  ```

### Task 2: Profile simplifier

Spec 4.4 (boundaries first, in one dimension).

**Interfaces:**
- Produces:
  ```cpp
  // The indices to keep of a profile of heights along a line, ascending, the first and the last always among them,
  // such that every height is within `tolerance` (vertical distance, metres) of the straight segment between the kept
  // indices either side of it. Douglas and Peucker's split rule: a segment whose worst height is further than the
  // tolerance is split at that height, the smallest index winning a tie, until none is. Deterministic. Throws
  // std::invalid_argument when heights has fewer than 2 values or a NaN, or tolerance is negative or not finite.
  [[nodiscard]] std::vector<int> simplifyProfile(std::span<const float> heights, double tolerance);
  ```

- [ ] **Step 1: Write the failing tests** in `tests/test_ProfileSimplifier.cpp`, tag `[profile]`:
  - a constant profile of 100 values gives `{0, 99}` at any tolerance, including 0;
  - the ramp `h[k] = 3 k` gives `{0, 99}` (a straight line has no error);
  - a spike of 10 at index 40 on a flat profile gives `{0, 39, 40, 41, 99}` at tolerance 5 (the chords from the ends to the spike pass 9.75 and 9.83 above the zeros beside it, so those split too) and `{0, 99}` at tolerance 10 (the error equals the tolerance and is allowed);
  - two equal spikes of 10 at 30 and 60: at tolerance 5 both are kept; at tolerance 9.9 only the first split happens and lands at 30 (the tie rule), giving `{0, 30, 99}`;
  - the bound: on 200 profiles of 257 random values in [0, 1000) (`std::mt19937` seeded 7) at tolerances 0, 1, 10, 100 and 1000, every index k satisfies `|h[k] - segment(k)| <= tolerance` for the kept indices around it, the first index is 0 and the last 256, the result is strictly ascending, and the same input gives the same output twice;
  - tolerance 0 on `{0, 1, 2, 3, 2, 1, 0}` gives `{0, 3, 6}` (collinear runs keep only their ends);
  - refusals: one value, a NaN, tolerance -1, tolerance NaN, each `std::invalid_argument`.
- [ ] **Step 2: Build; expect** the missing-header errors.
- [ ] **Step 3: Implement.** Recursion depth is the profile's length in the worst case (a ramp of noise); use an explicit stack of (first, last) segments, processed smallest-first-index first so that the output order is independent of the stack discipline, then sort the kept indices.

**Interfaces:**

- Produces (in `SolidMesh.h`):
  ```cpp
  // The outline of a surface as its four sides, each a list of vertex numbers from the side's first corner to its last
  // in the order solidMesh walks them: south from west to east, east from south to north, north from east to west,
  // west from north to south. A corner is the last vertex of one side and the first of the next (west's last is
  // south's first).
  struct Boundary { std::array<std::vector<std::uint32_t>, 4> sides; };  // south, east, north, west
  // The regular grid's boundary, for a surface surfaceMesh made: vertex j cols + i.
  [[nodiscard]] Boundary gridBoundary(int cols, int rows);
  // The printable solid from a surface and its boundary: the surface's vertices and triangles first and unchanged,
  // then four bottom corners under the first vertices of the south, east, north and west sides, then the walls (south,
  // east, north, west, each cut as the monotone polygon of solidMesh's header), then the two base triangles.
  // Throws std::invalid_argument when a side has fewer than 2 vertices, when consecutive sides do not share their
  // corner, when a side's vertices do not all share the coordinate across the wall (y on the south and north sides, x
  // on the east and west) or are not strictly in order along it, when a vertex is not above planeZ, when planeZ is not
  // finite, or when a vertex number is out of range.
  [[nodiscard]] Mesh solidFromSurface(const Mesh& surface, const Boundary& boundary, float planeZ);
  // surfaceTriangles + the sides' sizes + 2: one wall triangle per top vertex of each side and the base's two.
  [[nodiscard]] std::uint64_t solidTriangleCount(const Boundary& boundary, std::uint64_t surfaceTriangles) noexcept;
  ```
  `solidMesh(surface, cols, rows, planeZ)` keeps its signature, checks and messages, and is implemented as `solidFromSurface(surface, gridBoundary(cols, rows), planeZ)`.

### Task 4: The greedy TIN over one chunk

Spec 4.3 and 4.4. This task simplifies a grid that fits in one chunk; Task 5 adds the lattice.

**Files:**
- Create: `src/mesh/Simplifier.h`, `src/mesh/Simplifier.cpp`
- Test: `tests/test_Simplifier.cpp`
- Modify: `CMakeLists.txt`

**Interfaces:**
- Consumes: `orient2d`, `inCircle`, `GridPoint` (Task 1); `simplifyProfile` (Task 2); `Mesh`, `Boundary`, `solidFromSurface`, `checkSolid` (Task 3).
- Produces (in `Simplifier.h`):
  ```cpp
  inline constexpr int kChunkCells = 2048;       // the lattice without tiles (spec 4.5)
  inline constexpr int kMostChunkCells = 16384;  // the largest side the predicates are exact for

  struct SimplifiedSurface {
    Mesh surface;        // in model units, in the frame of surfaceMesh
    Boundary boundary;   // the window's outline, for solidFromSurface
    std::uint64_t gridVertices = 0;   // cols x rows
    std::uint64_t gridTriangles = 0;  // 2 (cols - 1)(rows - 1)
  };

  // Simplifies a grid of cols x rows heights in metres, row by row from the north-west corner as resampleQuadratic
  // gives them, to a TIN within toleranceM of every sample (spec 4.3), then places it in model units exactly as
  // surfaceMesh would: x = i widthM / (cols - 1) scale, y = (rows - 1 - j) heightM / (rows - 1) scale,
  // z = max(h, levelM) zScale scale. Chunks of chunkCells x chunkCells cells from the north-west corner (spec 4.5).
  // Vertices come chunk by chunk, each chunk's boundary vertices before its interior ones in insertion order, and a
  // vertex shared by chunks appears once. Triangles are counter-clockwise seen from above.
  // Throws std::invalid_argument when cols or rows is below 2, heights does not hold cols x rows values or holds a
  // NaN, toleranceM is negative or not finite, chunkCells is below 1 or above kMostChunkCells, or widthM, heightM,
  // zScale, scale or levelM fails surfaceMesh's checks.
  [[nodiscard]] SimplifiedSurface simplifyGrid(const std::vector<float>& heights, int cols, int rows,
                                               double toleranceM, double widthM, double heightM, double zScale,
                                               double scale, double levelM, int chunkCells = kChunkCells);
  ```

- [ ] **Step 1: Write the failing tests** in `tests/test_Simplifier.cpp`, tag `[simplify]`, with a test helper `double surfaceHeightAt(const SimplifiedSurface&, int cols, int rows, int i, int j)` that finds the triangle containing grid sample (i, j) in model coordinates (barycentric test in double, inclusive on edges) and interpolates its z, and `void checkGuarantees(const SimplifiedSurface& s, const Grid& g, int cols, int rows, double tol)` which asserts: the corners (0,0), (cols-1,0), (0,rows-1), (cols-1,rows-1) are vertices; every vertex coincides with a sample at that sample's height; every boundary side's vertices lie on its edge and the four corners are shared between sides as `Boundary` requires; every triangle's `(b - a) x (c - a)` has positive z; every vertex is used; `|surfaceHeightAt(i, j) - h(i, j)| <= tol + 1e-6` for every sample; and `checkSolid(solidFromSurface(s.surface, s.boundary, planeZ)).ok()` with `planeZ` below the lowest height. Cases, all with `chunkCells` large enough for one chunk unless said:
  - a 9 x 7 plane `h = 2 i + 3 j` at tolerance 0.5: 4 vertices, 2 triangles, `gridVertices == 63`, `gridTriangles == 96`;
  - a 9 x 7 flat grid with a spike of 10 at (4, 3) at tolerance 5: the spike is a vertex, the guarantees hold, and there are at most 9 vertices (the corners, the spike, and at most its four neighbours, which the tent's slopes bring within tolerance); at tolerance 10 exactly 4 vertices and 2 triangles, the spike's error being allowed;
  - a 9 x 7 flat grid with a spike of 10 on the south side at (4, 6) at tolerance 5: the side profile keeps it, so it is a vertex of the south side, and the guarantees hold;
  - 64 x 48 random heights in [0, 100) (seed 11) at tolerances 0, 0.5, 5, 50, 200: `checkGuarantees` passes; at 200 the result is 2 triangles; at 0 every sample is a vertex (3072);
  - the 64 x 48 "fractal" grid `h(i, j) = 50 sin(2 pi i / 64) + 20 sin(2 pi j / 48) + 5 sin(2 pi (i + j) / 16)` at tolerance 2: `checkGuarantees` passes and the vertex count is under half of 3072;
  - tolerance 1e-9 on the random grid ends with 3072 vertices (Review Focus 1; random float heights make an exact coincidence with a plane through other samples vanishingly unlikely, and a seed change is the remedy if one ever occurs);
  - 2 x 2, 2 x 9 and 9 x 2 grids (Review Focus 2): corners only, 2 triangles, the solid is a box or a ribbon that `checkSolid` accepts;
  - determinism: the fractal grid at tolerance 2 simplified twice gives identical vertex and triangle vectors;
  - refusals: `cols` 1, a NaN height, `toleranceM` -1, `chunkCells` 0 and 16385, `scale` 0, each `std::invalid_argument`.
- [ ] **Step 2: Build; expect** the missing-header errors.
- [ ] **Step 3: Implement** one chunk's simplification, the chunk being the whole grid for now, as a private function the lattice of Task 5 will call per chunk. The algorithm, which the signature and tests do not determine:
  - Work in chunk-local `GridPoint`s (column and row within the chunk). Simplify each side with `simplifyProfile` on the heights along it; start the triangulation from the four corners as two triangles and insert the sides' kept samples onto the hull edges (an insertion on an edge splits the triangle there).
  - Each triangle holds its worst sample and that sample's vertical error: the plane through its three vertices is evaluated at a sample by barycentric weights from `orient2d` (exact integers) and the three heights in double. Samples are scanned row by row within the triangle's bounding box, the span per row found with `orient2d >= 0` against the three edges; a sample on an edge may be scanned by both triangles (deviation 2). Ties for the worst sample go to the smallest row, then the smallest column.
  - A max-heap of (error, triangle, version) with lazy invalidation gives the next insertion: stop when the top's error is at most the tolerance; otherwise insert its worst sample, splitting the triangle into three, or both triangles into four when the sample lies on an interior edge; legalise with Lawson flips judged by `inCircle` (no flip at 0), never across a hull edge; rescan every triangle created or changed and push it.
  - Interior insertions never touch a side: every sample on a side is within tolerance of the side's segments, so its error there is at most the tolerance and it is never the worst above it.
  - Emit vertices in insertion order (sides first) and triangles wound counter-clockwise in model coordinates (the row axis points south, so a triangle counter-clockwise in local coordinates is emitted with two corners swapped); the `Boundary` is the four side lists in `Boundary`'s order.
- [ ] **Step 4: Run** `./build/demdl_tests "[simplify]"`; expect all passed.
- [ ] **Step 5: Commit** `feat: greedy-insertion TIN simplifier within a tolerance`.
